## 1. 最终引脚映射（**实测修正过，和早期文档不同**）

早期文档把左右标反了。经单侧标定（`ml` / `mr`）确认，实际接线是：

| 侧 | `STEPPER_L` = 机器人**左** | `STEPPER_R` = 机器人**右** |
|---|---|---|
| 相 A | PB1 | PA11 |
| 相 B | PB3 | PA12 |
| 相 C | PB4 | PA15 |
| 相 D | PB8 | PB0 |
| 步进时基 | TIM4 | TIM1 |
| 原始 `+` 方向 | **前进** | **后退** |

对应 `app_config.h`：

```c
#define STEPPER_A_PORTS  { GPIOB, GPIOB, GPIOB, GPIOB }   /* 左 */
#define STEPPER_A_PINS   { GPIO_Pin_1, GPIO_Pin_3, GPIO_Pin_4, GPIO_Pin_8 }
#define STEPPER_B_PORTS  { GPIOA, GPIOA, GPIOA, GPIOB }   /* 右 */
#define STEPPER_B_PINS   { GPIO_Pin_11, GPIO_Pin_12, GPIO_Pin_15, GPIO_Pin_0 }

#define STEPPER_L_DIR_SIGN  (+1)   /* 左侧：原始 + 即前进 */
#define STEPPER_R_DIR_SIGN  (-1)   /* 右侧：原始 + 是后退 */
```

> **接线一根都不用动** —— 只在软件里换哪组引脚算"左"。
>
> PA15 / PB3 / PB4 是 JTAG 引脚，`Stepper_Init()` 里已执行
> `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)` 释放，
> PA13/PA14 的 SWD 保留，不影响下载。

## 2. 步进模式与速度

```c
#define STEPPER_FULLSTEP_EN  1        /* 1 = 4 拍全步（2038 步/圈） */
#define STEPPER_ENABLE       1        /* 0 = 完全禁用步进（安全排查用） */
```

| 模式 | 步/圈 | 特点 |
|---|---|---|
| **全步（当前）** | **2038** | 两相常通电，扭矩大、速度快 |
| 半步 | 4076 | 平滑、分辨率高、慢 |

### 速度档（履带 30 mm 轮）

| 档位 | Hz | 线速度 | 用途 |
|---|---|---|---|
| 0 | 120 | 5.5 mm/s | 蜗速，精确定位 |
| 1 | 200 | 9.2 mm/s | 慢 |
| **2** | **300** | **13.9 mm/s** | **标准档（已验证）** |
| 3 | 600 | 27.7 mm/s | 快，需实测确认不丢步 |

```c
#define STEPPER_START_HZ        120u   /* 起步频率，斜坡起点 */
#define STEPPER_ACCEL_HZ_PER_MS 4u
#define STEPPER_HZ_MAX          700u
```

> ⚠️ **不要用档位 3 以上的步频做长距离运动。**
> 实测 `fwd 2000 3`（600Hz 档，曾试到 800Hz）在 5V 下会让 28BYJ-48
> **完全失步**，表现为剧烈抖动或转子被磁场拖着转。
> 5V 全步的可靠上限就在 300~600 Hz 之间。

## 3. 命令速查

| 命令 | 作用 |
|---|---|
| `fwd [步数] [档位]` | 前进，默认 2000 步 @档位 2 |
| `bck` / `lft` / `rgt` | 后退 / 原地左转 / 原地右转 |
| **`st`** | **立即停止（独立停止命令，无条件生效）** |
| **`stc`** | 立即停止 + 清除热保护冷却（台架调试） |
| `mv <dir> [档位] [步数]` | 直接指定 dir（0进 1退 2左 3右 4停） |
| `ml <步数>` / `mr <步数>` | **只驱动左 / 右电机**（原始方向，有正负） |
| `dcal` | 方向标定：依次跑单侧 4 条 |
| `sst` | 读回电机实时状态（位置/剩余/频率/故障） |
| `lstat` | 读回链路健康计数器 |
| `tick` | 测量 1 ms 时基是否准确 |
| `end [次数] [步数]` | 耐久测试，逐轮核对位置 |
| `cal` | 依次跑 fwd/bck/lft/rgt（双电机复合，观察有歧义） |

### 停止命令为什么单独做

```c
case OP_MOTOR_STOP:              /* 0x0C */
    handle_motor_stop(f);
```

不复用 `MOVE(dir=4)` 的原因：
1. 停止是**安全动作**，不能依赖上位机把 `dir` 算对
2. 必须**无条件生效** —— 不论是否在运动、是否故障、是否冷却中

## 4. 验收结果

### 已通过的判据

| # | 判据 | 实测 |
|---|---|---|
| 1 | 精确步数 | `fwd 2400` → `position=2400` 一步不差 |
| 2 | 双向归零 | `bck 2400` → `position=0` |
| 3 | 8 秒连续运动 | 完整执行，`trips=0` |
| 4 | `MOTION_DONE` 上报 | L/R 都收到，位置一致 |
| 5 | 左右同步 | 连续 10 轮 `L−R = 0` |
| 6 | 耐久无漂移 | `end 10 2000`：**20000/20000，偏差 0.00%** |
| 7 | 方向正确 | fwd/bck/lft/rgt 四条全对 |
| 8 | 时基准确 | `tick` 两次实测 +0.60% / +0.72% |
| 9 | 链路零丢帧 | `lstat`：1222 好帧、**0 坏帧、0 溢出** |
| 10 | 热保护不误触发 | 5V 档位 2 下 `trips` 恒为 0 |

### 硬件配置

- 电机：2 × 28BYJ-48（5 线，带 1:64 减速箱）
- 驱动：2 × ULN2003 模块
- **电机供电：5 V**（12V→5V 降压模块，≥2A）
- 履带驱动轮：30 mm
- 8 路 IN 线各加 10 kΩ 下拉
- 所有 GND 星形汇合到电源负极

> 从 12V 改 5V 的原因：12V 下双机同时运转时 ULN2003 温升可达 74~95 °C，
> 而且 28BYJ-48 线圈本身额定 5V，12V 长期运行功率是额定的 5.8 倍。
> 改 5V 后：单相 100 mA / 0.5 W，温升 25~36 °C，并且可以放开限时。

## 5. 热保护（5V 配置）

```c
#define STEPPER_SUPPLY_5V       1   /* 决定下面三个阈值 */
  STEPPER_MAX_RUN_MS         60000u   /* 单次连续 60 秒 */
  STEPPER_COOLDOWN_MS        500u
  STEPPER_MAX_OVERLAP_MS     60000u   /* 双机同时 60 秒 */
```

切回 12V 时改成 `STEPPER_SUPPLY_12V`，阈值自动变成 8s / 2s / 3s。

> **切换供电电压必须同步改这个宏。** 否则热保护阈值和实际硬件不匹配。

## 6. 调试踩坑记录（**这些坑都会重现，务必记住**）

| # | 现象 | 根因 | 修法 |
|:--:|---|---|---|
| 1 | 编译 30 个"标识符未定义" | PowerShell 单引号里的 `` `r`n `` 被当成字面字符插进源码，`#include` 被吞 | 已加 `tools/check_source_sanity.py`，编译前先跑 |
| 2 | 动作精确停在 1.29 秒 | **uint32 下溢**：`LinkSvc_Dispatch` 里 `s_last_frame_ms` 可能比主循环的 `now` 晚 1 ms，`now - last` 变 42 亿 → 误报心跳丢失 → 安全联锁停电机 | 所有时间差先比大小再相减 |
| 3 | 电机只跑 1 秒 | PC 工具动作期间不发心跳 | 工具在动作期间每 300 ms 发 PING（真实 A7Z 也须如此，≤500 ms） |
| 4 | 热故障永久锁存 | `s_fault = FAULT_THERMAL` 不清除，联锁杀掉之后每一次 MOVE | 改成"按当前是否在冷却"判定，冷却结束自动恢复 |
| 5 | 左右分叉（L=8914 / R=8895） | `Stepper_MoveBoth` 只在一侧启动失败时不回滚 | 任一侧失败就回滚另一侧 |
| 6 | 左右方向怎么调都不对 | **物理左右标反了** —— `DIR_SIGN` 只能修"前进极性"，修不了"哪组引脚是左" | 用 `ml`/`mr` 单侧标定，同时改引脚映射和 `DIR_SIGN` |
| 7 | `ACK(0x2E)` 之类的怪状态码 | MOVE 的 ACK 把预测距离放在了 `status` 位置 | ACK 统一 `payload[0]=status`、`payload[1]=距离` |
| 8 | 高步频电机狂转/不动 | 全步模式下 600~800 Hz 相当于半步 1200~1600 Hz，远超 5V 能力 | 标准档固定 300 Hz |

### 两条通用纪律

**① 协议联调阶段必须关掉阻塞调试输出**

```c
#define APP_DEBUG_TEXT        0
#define DEBUG_STATUS_PRINT    0
```

`Serial_Printf` 是阻塞发送，`handle_move` 里它在 ACK 之前执行，
会推迟应答并打乱主循环时序。

**② 方向类问题一律用单侧命令定位**

`fwd` / `lft` 都是双电机复合运动，任一符号错就看不出是哪一处。
`ml` / `mr` 只驱动一侧、且**不经过 `DIR_SIGN` 换算**，
"正数让轮子往哪走"是唯一确定的硬件事实。

## 7. 已知限制（留给后续阶段）

| 限制 | 说明 |
|---|---|
| **无编码器** | `position` 只统计"MCU 发了多少脉冲"，不代表电机真转了 |
| **无桌沿保护** | TOF 未接入，机器人会直接冲出桌面 |
| **速度上限低** | 28BYJ-48 天生慢；想快只能换大轮或换 42 步进 + A4988 |
| **失步不可检测** | 只能在标定时用 `sst` 对比 |

> 无编码器这条要特别注意：耐久测试"位置 20000 一步不差"只证明
> **脉冲数正确**，不证明**机械真的走了 20000 步**。
> 真正的闭环需要编码器或限位开关做参考点。
