# 上位机（A7Z）对接手册

> **本文是下位机协议的唯一权威说明。**
> README §6 只是摘要，与本文冲突时以本文为准。
>
> | 项 | 值 |
> |---|---|
> | 对应固件 | `M0 ~ M9`（`impl` 位图 = `0x3F`） |
> | 物理链路 | USART1，115200 8N1 |
> | 更新日期 | 2026-11-01 |

---

## 1. 物理层

### 1.1 接线

| STM32 | 方向 | A7Z 40-pin | 说明 |
|---|---|---|---|
| **PA9**（USART1_TX） | → | **Pin 18**（PJ25 / UART4-RX） | MCU → A7Z |
| **PA10**（USART1_RX） | ← | **Pin 16**（PJ24 / UART4-TX） | A7Z → MCU |
| GND | — | GND | **必须共地** |

> ⚠️ **TX 接 RX，交叉接。** 对接错的表现是"完全没有回应"，
> 而不是收到乱码 —— 因为根本不会有电平翻转。
>
> ⚠️ **不要接 5V 或 3.3V。** 两侧各自供电，只连 TX/RX/GND 三根。

### 1.2 串口参数

```text
115200 bps · 8 数据位 · 无校验 · 1 停止位 · 无流控
```

- A7Z 侧设备节点：`/dev/ttyS4`（UART4）
- **注意**：A7Z 现有代码里 UART4 默认是 **9600**（给 TTS 用的），
  对接前必须先改到 115200，否则收到的全是错位的字节。

### 1.3 电平

STM32 是 3.3V CMOS，A7Z IO 也是 3.3V，**不需要电平转换**。

## 2. 帧格式

### 2.1 结构

```text
偏移  长度  字段      说明
 0     1    SOF       固定 0xA5
 1     1    TYPE      0x01=CMD(上位机→MCU) 0x02=ACK 0x03=EVT
 2     2    SEQ       小端，上位机自增，MCU 原样回显
 4     1    OP        操作码
 5     1    LEN       PAYLOAD 字节数，0 ~ 200
 6     LEN  PAYLOAD
 6+LEN  2    CRC16     小端
```

**总长度 = 8 + LEN**，最短 8 字节（LEN=0），最长 208 字节。

### 2.2 CRC

| 项 | 值 |
|---|---|
| 算法 | CRC16-CCITT-FALSE |
| 多项式 | `0x1021` |
| 初值 | `0xFFFF` |
| 输入/输出反转 | 否 |
| **覆盖范围** | **SOF 起到 PAYLOAD 末字节**（即前 `6+LEN` 字节，**包含 0xA5**） |
| 校验向量 | `"123456789"` → `0x29B1` |

> ⚠️ **CRC 是从 SOF 开始算的**，不是从 TYPE 开始。
> 这一点最容易写错，错了的表现是"所有帧都被判坏帧"。

### 2.3 解析建议

| 情形 | 建议处理 |
|---|---|
| CRC 错 | 丢弃，继续找下一个 `0xA5` |
| LEN > 200 | 视为假 SOF，跳到下一字节重新同步 |
| 帧间字节间隔 > 100 ms | MCU 侧会丢弃半帧，上位机侧也建议同样处理 |
| 收到未知 OP | 忽略该帧，不要断开连接 |

### 2.4 LEN 上限

`LEN` 最大 **200**。

| 用途 | 实际上限 |
|---|---|
| 普通命令 | 4 字节以内 |
| TTS 原始 TW-TTS 帧 | 200 |
| TTS UTF-8 正文 | **190**（MCU 会加 5 字节帧头） |

> 旧版 README 写"0~64"是错的，已更正为 200。

## 3. ★ 应答有两种风格（最容易踩的坑）

MCU 的应答帧 `TYPE` 恒为 `0x02`，但 `OP` 字段有两种写法：

### 风格 A：普通命令 → 固定用 ACK / NAK

| OP | 名称 | PAYLOAD |
|---|---|---|
| `0x81` | ACK | `status(1)`，个别命令多 1 字节（见各命令） |
| `0x82` | NAK | `status(1) + detail(1)` |

### 风格 B：查询/诊断命令 → **回显请求的 OP**

| 请求 OP | 应答 OP | PAYLOAD |
|---|---|---|
| `0x06` PING | **`0x86` PONG** | 11 字节 |
| `0x08` GET_CONFIG | **`0x87` CONFIG** | 4 字节 |
| `0x09` STEPPER_STAT | **`0x09`** | 24 字节 |
| `0x0A` LINK_STAT | **`0x0A`** | 32 字节 |

> **所以上位机不能只判断 `OP == 0x81`。**
> 正确的匹配方式是：**先比 `SEQ`，再看 `OP`**。
> 自己发出去的 SEQ 是多少，就等回显同样是那个 SEQ 的帧。

### 3.1 请求与应答的配对

```text
上位机发： TYPE=0x01  SEQ=N  OP=X  ...
MCU 回：  TYPE=0x02  SEQ=N  OP=Y  ...
                    ↑ 一定相同   ↑ 见上表
```

`SEQ` 由上位机自增（0~65535 循环），MCU 原样回显。**不做去重**，
同一 SEQ 发两次会执行两次。

### 3.2 周期性主动事件不占用 SEQ

主动事件（`0x91~0x96`）的 `SEQ` 恒为 **0**，且 `TYPE = 0x03`。
上位机解析时应按 `TYPE` 分流，不要靠 SEQ 匹配。

## 4. 命令详解

### 4.1 `0x01` MOVE — 运动

**请求**

```text
payload: dir(1) + speed(1) + steps(2, 小端)
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `dir` | 0 / 1 / 2 / 3 / 4 | 前进 / 后退 / 原地左转 / 原地右转 / 停止 |
| `speed` | 0 ~ 3 | 档位，见下表；**其他值按 2 处理** |
| `steps` | 1 ~ 65534 | 单侧步数 |
| | `0xFFFF` | **持续运动**，直到 STOP 或热保护截断 |

**速度档位 → 实际频率**

| speed | Hz | 前进速度（实测，5V 全步） |
|---|---|---|
| 0 | 120 | ≈ 5.5 mm/s |
| 1 | 200 | ≈ 9.2 mm/s |
| 2 | **300（默认）** | ≈ 13.9 mm/s |
| 3 | 600 | ≈ 27.7 mm/s（长距离会丢步，慎用） |

> 换算基准：2038 整步/圈（全步模式），轮径 30 mm，即 94.2 mm/圈。

**应答**

| 情况 | 应答 |
|---|---|
| 正常启动 | `ACK(0x81)` payload = `[0x00, mm10]` |
| `dir=4` 停止 | `ACK(0x81)` payload = `[0x00]` |
| 参数错（dir>3 / steps=0 / LEN<4） | `NAK(0x82)` = `[0x05, 0x01]` |
| 桌沿/障碍/盲走拦截 | `NAK(0x82)` = `[0x03, 故障码]` |
| 电机忙 | `NAK(0x82)` = `[0x02, 0x01]` |
| 热保护中 | `NAK(0x82)` = `[0x03, 0x01]` ⚠️ 见下 |

> ⚠️ **`NAK(0x03, 0x01)` 里的 `0x01` 是操作码 MOVE，不是故障码。**
> 这条来自"步进层拒绝启动"，`detail` 填的是 `op`。
> 而 `NAK(0x03, 0x02)` / `NAK(0x03, 0x03)` 来自"TOF 闸门"，
> `detail` 填的才是故障码（桌沿 / 障碍）。
>
> 两者语义不一致，是历史遗留。**想确认到底是不是过热，
> 看 `STEPPER_STAT` 的 `flags` bit1（cooling）**，别只看 NAK。

**`mm10` 是什么**

预测行走距离，单位 **0.1 mm**，**饱和到 255**。

```text
mm10 = steps × π × 30 / 2038 × 10
```

> 例：`steps=2000` → 924 mm10（92.4 mm），但因为 924 > 254，
> 实际回的是 `0xFF`。**看到 0xFF 表示"距离超过 25.4 mm"，不是错误。**

**MOVE 的特殊性**

`dir = 4`（停止）虽然走 MOVE 操作码，但**按 SAFETY 类处理，不受控制权限制**。
换句话说：只要上位机或蓝牙任一方发 `MOVE dir=4`，都会立刻停。

**持续运动的注意**

`steps = 0xFFFF` 不是真的无限。会被以下任一条件截断：

- 收到 `MOTOR_STOP` 或 `MOVE dir=4`
- 心跳丢失（1000 ms）
- 热保护到时（5V 供电下单次上限 60 秒）
- 桌沿/障碍故障

### 4.2 `0x02` SERVO — 舵机

**请求**

```text
payload: deg(int8) + ms(2, 小端)      ← 固定 3 字节，ms 不可省略
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `deg` | -45 ~ +45 | 有符号；超限**钳位**而非报错 |
| `ms` | 0 ~ 65535 | 缓动时长；0 = 立即到位 |

**应答**

| 情况 | 应答 |
|---|---|
| 正常 | `ACK` `[0x00]` |
| 角度被钳位 | `ACK` `[0x01]` ← **注意是 ACK 不是 NAK** |
| 舵机被配置关闭 | `NAK` `[0x06, 0x02]` |
| 长度不足 3 | `NAK` `[0x05, 0x02]` |

> ⚠️ **`ms` 不是可选的。** 旧版 README 写"角度 + 可选时长"是错的，
> 固件要求 `LEN >= 3`，只发 1 字节会收到 `NAK(0x05)`。

> 舵机默认是**关闭**的（`CFG_SERVO_EN = 0`），需要先 `SET_CONFIG` 打开，
> 否则一律 `NAK(0x06)`。

---

### 4.3 `0x03` TTS — 语音转发

MCU 把数据通过 USART2（9600 8N1）转给 TW-TTS 模块。`payload` 有两种形态：

| 形态 | 判定 | 处理 |
|---|---|---|
| **原始帧** | 首字节 = `0xFD` | 原样转发 |
| **UTF-8 正文** | 其他 | MCU 自动包成 `FD len_hi len_lo 01 04 正文` |

**A7Z 正式接入走原始帧**，协议与它已验证过的 `uart_tts.cxx` 完全一致：

```c
// A7Z 侧原有代码，不用改
tts_text_frame(text, 0x04, frame);   // 得到 frame
// 把 frame 原样放进 OP_TTS 的 payload
```

**长度限制**

| 形态 | 上限 |
|---|---|
| 原始帧 | 200 字节（= LEN 上限） |
| UTF-8 正文 | 190 字节（约 63 个汉字） |

**应答**

| 情况 | 应答 |
|---|---|
| 已入队 | `ACK` `[0x00]` |
| 已入队但发送缓冲有积压 | `ACK` `[0x02]` ← 仍算成功，但要**降速** |
| 缓冲满 | `NAK` `[0x02, 0x03]` ← **整帧未发送，可原样重发** |
| 正文超长 | `NAK` `[0x01, 0x03]` |
| TTS 被关闭 | `NAK` `[0x06, 0x03]` |

> ⚠️ **`ACK` 只代表"字节进了发送队列"，不代表"已经念完"。**
> 9600 波特下每秒只能发 960 字节（约 5 个汉字/秒）。
> 模块不回播放完成状态，串行播报必须按字数估算等待。

> ⚠️ **收到 `NAK(0x02)` 要重发整帧**，不要只发剩余部分 ——
> 半截帧会让模块念到一半停住且无法自愈。

### 4.4 `0x04` TOF_CFG — 调整轮询间隔

**请求**

```text
payload: poll_ms(1)
```

| 取值 | 说明 |
|---|---|
| 10 ~ 255 | 两颗传感器之间的间隔（毫秒） |
| < 10 | 钳位到 10，回 `ACK(0x01)` |

**应答**

| 情况 | 应答 |
|---|---|
| 生效 | `ACK` `[0x00]` |
| 被钳位 | `ACK` `[0x01]` |
| 一颗 TOF 都不在线 | `NAK` `[0x06, 0x04]` |

> 该命令**只改间隔，不改启用集**。启用哪几颗要走 `SET_CONFIG`。
>
> 注意：一轮的总周期 ≈ `poll_ms × (在线颗数 − 1) + 测量时间 × 在线颗数`。
> 20 ms 测量预算下，**当前 2 颗约 50 ms 一轮**，4 颗约 120 ms。
> 桌沿检测的响应延迟就是"一轮"，所以别把 `poll_ms` 调得太大。

### 4.5 `0x05` CLEAR_FAULT — 清故障

**请求**

```text
payload: flag(1) [blind_ack(1)]
```

| flag | 含义 |
|---|---|
| `0x00` | 清全部可清故障（兼容旧上位机） |
| `0x01` | 清桌沿 |
| `0x02` | 清障碍 |

**盲走模式的特殊握手**

如果底部 TOF 全关（盲走模式），清故障**必须**带上第二个字节：

```text
payload: 0x00, 0x5A
```

否则返回 `NAK(0x03, 0x0A)`。

> 这是刻意设计：关掉安全传感器必须是一个"刻意动作"，
> 而且这份许可**不持久化**，每次冷启动都要重新确认。

**应答**

| 情况 | 应答 |
|---|---|
| 清除成功 | `ACK` `[0x00]` |
| 盲走模式但没带 0x5A | `NAK` `[0x03, 0x0A]` |
| 长度不足 1 | `NAK` `[0x05, 0x05]` |

### 4.6 `0x06` PING — 心跳

**请求**：`LEN = 0`，无 payload。

**应答**：`TYPE=0x02, OP=0x86(PONG)`，11 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | `uptime_ms`，小端，开机以来的毫秒数 |
| 4 | 1 | `fault` 当前故障码 |
| 5 | 4 | `config` 配置字，小端 |
| 9 | 1 | `flags` |
| 10 | 1 | `impl` 功能实现位图 |

**flags 位定义**

| 位 | 含义 |
|---|---|
| bit0 | 1 = 配置来自 Flash；0 = 本次上电用的是默认值 |
| bit1 | 1 = 处于盲走模式（底部 TOF 全关） |

**impl 位定义（判断固件版本）**

| 位 | 功能 |
|---|---|
| bit0 | SERVO |
| bit1 | MOVE |
| bit2 | TTS |
| bit3 | TOF |
| bit4 | SET/GET_CONFIG |
| bit5 | CLEAR_FAULT |

当前固件应为 **`0x3F`**（全都有）。

> **上位机启动时建议先发一次 PING 核对 `impl`。**
> 少了对应位就说明板子里跑的是旧固件，
> 这样能把"没刷固件"和"接线有问题"区分开。

---

### 4.7 `0x07` SET_CONFIG — 写配置

**请求**：`LEN` 必须**恰好 4**，payload = 32 位配置字（小端）。

**应答**

| 情况 | 应答 |
|---|---|
| 成功 | `ACK` `[0x00]`，随后主动发一条 `EVT_CONFIG_CHANGED` |
| Flash 写失败 | `NAK` `[0x07, 0x00]` |
| LEN 不等于 4 | `NAK` `[0x05, 0x07]` |

> **写失败时内存中的配置仍然生效**（本次运行按新配置走），
> 只是重启后会回到旧值。上位机应把 `NAK(0x07)` 当作"需要重试或提示"。

**运行期立即生效的部分**：舵机开关会当场初始化/关闭，不用重启。

---

### 4.8 `0x08` GET_CONFIG — 读配置

**请求**：`LEN = 0`。

**应答**：`TYPE=0x02, OP=0x87(CONFIG)`，4 字节配置字（小端）。

### 4.9 `0x09` STEPPER_STAT — 电机实时状态（诊断）

**请求**：`LEN = 0`。

**应答**：`TYPE=0x02, OP=0x09`，24 字节

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | 左电机 `position`，int32 小端，累计步 |
| 4 | 4 | 左电机 `remaining`，int32，剩余步（0 = 已停） |
| 8 | 2 | 左电机 `cur_hz`，uint16 |
| 10 | 1 | 左电机 `flags`：bit0 running，bit1 cooling |
| 11 | 4 | 右电机 `position` |
| 15 | 4 | 右电机 `remaining` |
| 19 | 2 | 右电机 `cur_hz` |
| 21 | 1 | 右电机 `flags` |
| 22 | 1 | 热跳闸累计次数（饱和 255） |
| 23 | 1 | 当前 `fault` |

**用途**：区分"命令没生效"和"命令生效但被拦了"。

| 现象 | 结论 |
|---|---|
| `remaining` 一直等于请求值、`running=0` | 命令根本没启动 |
| `remaining` 在减、`running=1` | 正常在走 |
| `remaining` 不减、`cooling=1` | 卡在热保护冷却 |
| `position` 和预期差很多 | 丢步（无编码器，只能看差值） |

> `position` 是**机器人坐标系**（前进为正），左右两侧数值应当相等。

---

### 4.10 `0x0A` LINK_STAT — 链路健康（诊断）

**请求**：`LEN = 0`。

**应答**：`TYPE=0x02, OP=0x0A`，32 字节

| 偏移 | 长度 | 字段 | 作用域 |
|---|---|---|---|
| 0 | 4 | `uptime_ms` | 全局 |
| 4 | 4 | 好帧数 | **发起本次查询的那条链路** |
| 8 | 4 | 坏帧数 | 同上 |
| 12 | 4 | 收到字节总数 | 同上 |
| 16 | 4 | 环形缓冲溢出次数 | 同上 |
| 20 | 4 | 距上一帧的毫秒数（从未收到过 = `0xFFFFFFFF`） | 同上 |
| 24 | 1 | 当前 `fault` | 全局 |
| 25 | 1 | `comm_lost`（两路都失联才为 1） | 全局 |
| 26 | 1 | 控制权：`0`=A7Z `1`=蓝牙 `0xFF`=无人 | 全局 |
| 27 | 1 | A7Z alive | 全局 |
| 28 | 1 | 蓝牙 alive | 全局 |
| 29 | 1 | 蓝牙端口是否已初始化 | 全局 |
| 30 | 2 | 保留（0） | — |

**怎么用**

| 现象 | 结论 |
|---|---|
| `好帧数` 在涨 | 通信正常 |
| `收到字节` 在涨但 `好帧数` 不涨 | **帧被 CRC/解析丢掉了** → 查波特率、CRC 算法 |
| `溢出次数` 在涨 | MCU 主循环太慢 → 上位机发太快，降频 |
| `距上一帧` 一直很大 | MCU 根本没收到 → 查接线（TX/RX 是否交叉） |

### 4.11 `0x0B` STEPPER_TEST — 单侧电机标定

**请求**

```text
payload: motor(1) + steps(4, 小端有符号)
```

| 字段 | 取值 |
|---|---|
| `motor` | 0 = 左，1 = 右 |
| `steps` | int32，**有符号**；正 = 原始相位递增方向 |

**应答**：`ACK` `[0x00]` / `NAK` `[0x02]`（忙）/ `NAK` `[0x03]`（过热）/ `NAK` `[0x05]`（参数错）

> 这个命令**不经过方向符号**，直接驱动单侧电机。
> 用途：`fwd/bck/lft/rgt` 是双电机复合动作，任一处符号错都表现为"整体不对"，
> 无法反推。只驱动一个轮子时，"正数让它往哪走"就是唯一确定的事实。
>
> **正常运行时不要用**，它是标定工具。

---

### 4.12 `0x0C` MOTOR_STOP — 立即停止

**请求**

```text
payload: [flags(1)]      ← 可省略
```

| flags 位 | 含义 |
|---|---|
| bit0 | 1 = 同时清除热保护冷却（**仅台架调试用**） |

**应答**：`ACK` `[0x00]`

> **无条件生效**：不管当前是否在运动、是否故障、控制权在谁手上。
> 这是 SAFETY 类命令，**不受仲裁限制**。
>
> 为什么不复用 `MOVE dir=4`：停止是安全动作，不该依赖
> "上位机把 dir 字段算对"。两个都保留，任选其一即可。

## 5. 状态码

| 值 | 名称 | 含义 | 上位机该怎么做 |
|---|---|---|---|
| `0x00` | OK | 成功 | — |
| `0x01` | CLAMPED | 参数越界，已钳位 | 可用，但应修正参数 |
| `0x02` | BUSY | 上一条动作未完成 | 等 `MOTION_DONE` 或稍后重试 |
| `0x03` | FAULT_LATCHED | 故障锁存 | 看 `detail`，注意 §5.1 的歧义 |
| `0x04` | CRC_ERROR | **固件从不主动返回** | 见下面的说明 |
| `0x05` | UNKNOWN_OP | 未知操作码或参数错 | **不要重试**，查协议 |
| `0x06` | FEATURE_DISABLED | 该功能被配置关闭 | 先 `SET_CONFIG` 打开 |
| `0x07` | FLASH_FAIL | 配置写入失败 | 内存已生效，可重试 |
| `0x08` | NOT_IMPLEMENTED | 保留，当前不会返回 | — |
| `0x09` | ARBITRATION | 控制权不在本通道 | 见 §8 |

> ⚠️ **收到坏帧时 MCU 什么都不发。**
> `0x04 CRC_ERROR` 只是历史定义，固件遇到 CRC 错会**静默丢弃**并计数，
> 不会回 NAK。
>
> 结果就是：**上位机如果发了坏帧，只会表现为"超时无应答"**。
> 想知道到底是"没收到"还是"收到了但坏了"，去看
> `LINK_STAT` 的**坏帧数**：
>
> | 好帧数 | 坏帧数 | 结论 |
> |---|---|---|
> | 不涨 | 不涨 | MCU 没收到 → 查接线 / 波特率 |
> | 不涨 | **在涨** | 收到了但 CRC/长度不对 → 查 CRC 算法 |
> | 在涨 | — | 通信正常 |

### 5.1 ⚠️ `detail` 字段的含义随 `status` 变化

这是协议的粗糙之处，必须按 status 分别解读：

| status | `detail` 含义 |
|---|---|
| `0x02` BUSY | 恒为 `0x01`（操作码 MOVE），不是故障码 |
| `0x03` FAULT_LATCHED | **两种含义，见下** |
| `0x05` UNKNOWN_OP | 出错的是哪个**操作码** |
| `0x06` FEATURE_DISABLED | 同上，操作码 |
| `0x09` ARBITRATION | 同上，操作码 |
| `0x07` FLASH_FAIL | 恒为 `0x00` |

**`0x03` 的两种含义（必须区分）**

| 来源 | `detail` | 含义 |
|---|---|---|
| TOF 闸门（`handle_move` 前半段） | `0x02` | **故障码**：桌沿 |
| TOF 闸门 | `0x03` | **故障码**：障碍 |
| `CLEAR_FAULT` | `0x0A` | **故障码**：盲走未确认 |
| 步进层（忙 / 过热） | `0x01` | **操作码 MOVE**，不是故障码 |

> 也就是说只有 `detail = 0x01` 那一条是"操作码"，其余是故障码。
> 恰好 `0x01` 作为故障码是 `HEARTBEAT_LOST`，但 TOF 闸门**永远不会**发这个值，
> 所以 `NAK(0x03, 0x01)` 只可能是"步进层拒绝（忙或过热）"。
>
> **稳妥做法：不要用 `detail` 单独判断故障，用 `PONG.fault` 或
> `STEPPER_STAT` 的第 23 字节确认。**

## 6. 故障码

| 值 | 名称 | 触发条件 | 恢复方式 |
|---|---|---|---|
| `0x00` | NONE | 正常 | — |
| `0x01` | HEARTBEAT_LOST | 两路链路都超过窗口没发帧 | 收到任意有效帧自动清 |
| `0x02` | EDGE | 底部 TOF 读距超过 `TOF_EDGE_MM`（默认 80 mm） | `CLEAR_FAULT` flag=0x01 |
| `0x03` | OBSTACLE | 前脸 TOF 读距小于 `TOF_OBSTACLE_MM`（默认 150 mm） | 障碍移开自动清 |
| `0x04` | THERMAL | 步进处于冷却期 | 冷却结束自动清 |
| `0x05` | TOF_INIT | 启用了一颗都没上线 | 复位 |
| `0x0A` | NO_EDGE_PROTECT | 底部 TOF 全关（盲走） | `CLEAR_FAULT(0x00, 0x5A)` |

### 6.1 故障同时出现时的上报优先级

```text
NO_EDGE_PROTECT  >  桌沿  >  障碍  >  心跳丢失  >  过热  >  TOF 初始化失败
```

`PONG` 里的 `fault` 字段只报**优先级最高的那一个**。

### 6.2 故障时的运动限制

| 故障 | 前进 | 后退 | 转向 |
|---|---|---|---|
| 桌沿 `EDGE` | ❌ | ✅（唯一允许） | ❌ |
| 障碍 `OBSTACLE` | ❌ | ✅ | ✅ |
| 心跳丢失 | 全部停止 | | |
| 过热 | 全部停止，等冷却 | | |
| 盲走 `NO_EDGE_PROTECT` | 全部禁止，直到确认 | | |

> 桌沿故障只放行后退，是因为"回退脱困"是唯一安全的动作；
> 再往前走就是掉下去。

## 7. 主动事件

`TYPE = 0x03`，`SEQ = 0`，**由 MCU 主动推给上位机**。

| OP | 名称 | PAYLOAD | 触发 |
|---|---|---|---|
| `0x91` | EDGE_DETECTED | `sensor(1) + dist_mm(2)` | 桌沿首次触发 |
| `0x92` | TOF_DATA | `mask(1) + d0..d3(2 each)` = 9 字节 | 每 200 ms |
| `0x93` | FAULT | `code(1)` | 故障首次出现 |
| `0x94` | MOTION_DONE | `motor(1) + position(4)` | 某侧电机走完 |
| `0x95` | OBSTACLE_DETECTED | `dist_mm(2)` | 障碍首次触发 |
| `0x96` | CONFIG_CHANGED | `config(4)` | `SET_CONFIG` 成功 |

### 7.1 字段细节

**`0x91` EDGE_DETECTED**

- `sensor`：传感器编号 `0~2`（底部三颗的索引）
- `dist_mm`：触发时的读数；`0xFFFF` 表示无效

**`0x92` TOF_DATA**

- `mask`：在线传感器的位图（TOF0=bit0 … TOF3=bit3）
- `d0..d3`：四路距离，各 2 字节小端
- **`0xFFFF` = 无效/未启用**，不是"距离 65535"

> 只装 TOF0 和 TOF3 时，`mask = 0x09`，`d1/d2` 恒为 `0xFFFF`。

**`0x94` MOTION_DONE**

- `motor`：0 = 左，1 = 右
- `position`：int32，机器人坐标系（前进为正）

> **左右两侧会各发一条。** 想判断"整个动作完成"，
> 需要等两条都到，或者用 `STEPPER_STAT` 看两只 `remaining` 都为 0。

**`0x93` FAULT**

只在上报标志从"已报"变为"未报"时发一次，**不会刷屏**。
所以在收到 `EVT_FAULT` 之后，`PONG` 里的 `fault` 才是持续可信的来源。

### 7.2 广播规则

事件会发给**所有在线链路**（A7Z + 蓝牙）。

例外：`TOF_DATA` 默认**不发给蓝牙**（`BT_VERBOSE_EVENTS = 0`），
因为蓝牙只是遥控通道，低波特率下这条流会把发送端堵死。

> 所以上位机不应该假设"事件只有我能收到"。
> 如果需要独占，先保证蓝牙不在线。

## 8. 双命令源仲裁

MCU 同时接受两路上位机：**A7Z（USART1）** 和 **蓝牙（USART3）**。

### 8.1 命令分三级

| 等级 | 包含的命令 | 是否受控制权限制 |
|---|---|---|
| **SAFETY** | `MOTOR_STOP`、`CLEAR_FAULT`、`MOVE dir=4` | ❌ **任何来源都执行** |
| **QUERY** | `PING`、`GET_CONFIG`、`STEPPER_STAT`、`LINK_STAT` | ❌ 总是执行 |
| **CONTROL** | `MOVE`（非停止）、`SERVO`、`TTS`、`TOF_CFG`、`SET_CONFIG`、`STEPPER_TEST` | ✅ **只有拥有者** |

### 8.2 控制权归属

```text
A7Z 在线  →  A7Z 拥有（A7Z 是"大脑"）
A7Z 失联  →  蓝牙接管
两个都不在 →  无人拥有（置心跳故障并停车）
```

**在线判定窗口**（距上一帧的时间）：

| 链路 | 窗口 |
|---|---|
| A7Z | **1000 ms** |
| 蓝牙 | 2000 ms（人工遥控节奏更慢） |

### 8.3 对上位机的影响

1. **只要 A7Z 保持在发帧，控制权就一直在 A7Z 手上**，蓝牙无法抢。
2. 控制权**切换瞬间，MCU 会调用 `Stepper_StopAll()`**。
   所以 A7Z 掉线重连后，**必须重新发 MOVE**，不会"接着刚才的动作继续跑"。
3. 非拥有者发 CONTROL 命令会收到 `NAK(0x09)`，`detail` 是操作码。

### 8.4 心跳契约（**必须遵守**）

> **运动期间，上位机必须每 ≤ 500 ms 发一次 `PING`（或任意有效帧）。**
>
> 否则 1000 ms 后 MCU 置 `HEARTBEAT_LOST` 并停止一切运动。

**这不是可选的优化，是硬约束。** 一个实际踩过的坑：

```text
发一次 MOVE 2400 后就不再发帧
→ 电机只走 1 秒多一点就停住
→ 现象看起来像"步数被截断"，实际是心跳超时
```

**建议**：

| 项 | 建议值 |
|---|---|
| 心跳周期 | **300 ms**（留 3 倍余量） |
| 判断失联的本地阈值 | 1500 ms |
| 上电宽限期 | MCU 上电后 **3000 ms** 内不判心跳丢失 |

> 宽限期是给 MCU 初始化用的（TOF 初始化约 1 秒）。
> 上位机如果开机就发命令，第一批可能落在宽限期内 —— 这是正常的，不算错误。

## 9. 配置字

### 9.1 位定义

| 位 | 名称 | 默认 | 说明 |
|---|---|---|---|
| bit0 | `SERVO_EN` | **0** | 舵机 |
| bit1 | `TTS_EN` | 1 | 语音转发 |
| bit2 | `BT_EN` | 1 | 蓝牙链路 |
| bit3 | `TOF0_EN` | 1 | 底部前（桌沿） |
| bit4 | `TOF1_EN` | **0** | 底部左（**当前未装**） |
| bit5 | `TOF2_EN` | **0** | 底部右（**当前未装**） |
| bit6 | `TOF3_EN` | 1 | 前脸（障碍） |

### 9.2 常用值

| 场景 | 配置字 | 命令 |
|---|---|---|
| **当前默认**（TTS + 蓝牙 + 两颗 TOF） | **`0x4E`** | `s 0000004E` |
| 再加舵机 | `0x4F` | `s 0000004F` |
| 四颗 TOF 全开（补齐硬件后） | `0x7E` | `s 0000007E` |
| 只留运动（全关外设） | `0x00` | ⚠️ 会进盲走模式 |

### 9.3 重要提醒

> ⚠️ **配置存在 Flash 里，重新烧固件不会覆盖。**
> 改了 `app_config.h` 的默认值只对"从没写过配置"的板子生效。
>
> 要让新默认值生效，必须：
> - 手动发一次 `SET_CONFIG`，或者
> - 擦除 Flash page 63（`0x0800FC00`）后再上电

## 10. 字节级示例

以下示例的 CRC 均由固件同一份实现生成，可直接对照。

### 10.1 PING（seq=1）

```text
A5 01 01 00 06 00 7A DA
 │  │  └─┬─┘ │  │  └─┬─┘
 │  │    │   │  │    └── CRC16
 │  │    │   │  └─────── LEN = 0
 │  │    │   └────────── OP = 0x06 PING
 │  │    └────────────── SEQ = 0x0001
 │  └─────────────────── TYPE = CMD
 └────────────────────── SOF
```

期望应答：

```text
A5 02 01 00 86 0B <uptime 4B> <fault 1B> <config 4B> <flags 1B> <impl 1B> <crc 2B>
```

### 10.2 MOVE 前进 speed=2 steps=2000（seq=3）

```text
A5 01 03 00 01 04 00 02 D0 07 20 1A
                  │  │  └──┬──┘
                  │  │     └── steps = 0x07D0 = 2000 (小端)
                  │  └──────── speed = 2 (300 Hz)
                  └─────────── dir = 0 (前进)
```

### 10.3 MOVE 停止（seq=4）

```text
A5 01 04 00 01 04 04 02 00 00 09 72
                     ↑     └──┬──┘
                     │        └── steps = 0（停止时不看）
                     └─────────── dir = 4 (停止)
```

### 10.4 MOTOR_STOP（seq=5）

```text
A5 01 05 00 0C 00 40 FF
```

### 10.5 SERVO +30°，立即（seq=6）

```text
A5 01 06 00 02 03 1E 00 00 3B 16
                  │  └──┬──┘
                  │     └── ms = 0（立即）
                  └──────── deg = 0x1E = 30
```

### 10.6 SET_CONFIG 0x4E（seq=7）

```text
A5 01 07 00 07 04 4E 00 00 00 CA 5F
                  └───────────┬────┘
                              └── config = 0x0000004E (小端)
```

### 10.7 CLEAR_FAULT 全清（seq=8）

```text
A5 01 08 00 05 01 00 2A D2
```

### 10.8 TOF_CFG 20ms（seq=9）

```text
A5 01 09 00 04 01 14 FE 1D
```

### 10.9 TTS 原始帧：音量 5（seq=10）

```text
A5 01 0A 00 03 09 FD 00 06 01 01 5B 76 35 5D B8 61
                  └──────────────┬──────────────────┘
                                 └── TW-TTS 参数帧（原样转发）
```

### 10.10 TTS UTF-8 正文"你好"（seq=11）

```text
A5 01 0B 00 03 06 E4 BD A0 E5 A5 BD 53 B3
                        └──────┬──────┘
                               └── "你好" 的 UTF-8 编码
```

MCU 会自动包成：

```text
FD 00 08 01 04 E4 BD A0 E5 A5 BD
   └─┬─┘
     └── len = 6 + 2 = 8
```

### 10.11 GET_CONFIG（seq=2）

```text
A5 01 02 00 08 00 A9 62
```

### 10.12 STEPPER_STAT / LINK_STAT

```text
A5 01 0C 00 09 00 C2 F3      ← STEPPER_STAT (seq=12)
A5 01 0D 00 0A 00 25 D0      ← LINK_STAT    (seq=13)
```

## 11. 上位机实现检查清单

按这个顺序实现，能少走很多弯路。

### 11.1 必做

- [ ] 串口参数 **115200 8N1**，无流控
- [ ] CRC 从 **SOF（0xA5）** 开始算，多项式 `0x1021`，初值 `0xFFFF`
- [ ] `SEQ` 自增，应答按 `SEQ` 配对（**不要只判断 `OP == 0x81`**）
- [ ] 主动事件按 `TYPE == 0x03` 分流，不看 `SEQ`
- [ ] 运动期间 **每 300 ms 发一次 PING**
- [ ] 上电先发 `PING`，核对 `impl == 0x3F`

### 11.2 建议

- [ ] 给每条命令设 500 ms 超时，超时重发最多 2 次
- [ ] `NAK(0x05)`（参数错）**不要重试**，直接报错
- [ ] `NAK(0x02)`（忙）等 `MOTION_DONE` 或 200 ms 后重试
- [ ] TTS 收到 `NAK(0x02)` 要重发**整帧**
- [ ] 收到 `ACK(0x01)` 说明参数被钳位，应记录并修正
- [ ] 把 `PONG.flags` bit1（盲走）当告警显示

### 11.3 不要做

- [ ] ❌ 不要假设 `LEN` 上限是 64（实际 200）
- [ ] ❌ 不要假设 `SERVO` 的 `ms` 可以省略（必须 3 字节）
- [ ] ❌ 不要把 `MOVE` ACK 的第二个字节当状态码（它是距离）
- [ ] ❌ 不要在收到 `NAK(0x09)` 后疯狂重试（控制权不在你手上）
- [ ] ❌ 不要依赖 `EVT_FAULT` 做持续状态（只发一次，用 `PONG.fault`）

## 12. 常见问题

| 现象 | 最可能的原因 | 排查方法 |
|---|---|---|
| 完全没回应 | TX/RX 没交叉，或没共地 | 万用表测 MCU 的 PA9 有没有电平变化 |
| 有回应但全是坏帧 | 波特率不对（A7Z 默认 9600） | 改到 115200 |
| 有回应但 CRC 总错 | CRC 从 TYPE 开始算了 | 改成从 SOF 开始 |
| 命令有 ACK 但电机不动 | 心跳没跟上 | 看 `LINK_STAT` 的好帧数，加 PING |
| 命令被 `NAK(0x09)` | 控制权在蓝牙手上 | 保持 A7Z 持续发帧 |
| 命令被 `NAK(0x03, 0x02)` | 桌沿故障 | `CLEAR_FAULT` flag=0x01 |
| 舵机不动 | `CFG_SERVO_EN = 0` | `SET_CONFIG` 打开，或 `s 0000004F` |
| TTS 没声音 | `CFG_TTS_EN = 0`，或模块没接 | `s 0000004E`，查 PA2 到模块 RXD |
| 电机走 1 秒就停 | **心跳超时** | 加 300 ms PING |
| 电机走不到指定步数 | 热保护（5V 下单次 60 秒） | 看 `STEPPER_STAT` 的 `cooling` 位 |

## 13. 已知限制

| 限制 | 说明 | 影响 |
|---|---|---|
| **无编码器** | `position` 只统计"发了多少脉冲"，电机真没转它不知道 | 高速丢步检测不到 |
| **桌沿有方向盲区** | 当前只装 1 颗底部传感器（TOF0，朝前） | **后退方向完全没有保护**，见 `TOF两传感器配置说明.md` |
| **TTS 无完成回调** | 模块不回播放状态 | 串行播报只能按字数估算 |
| **TTS 9600 是硬瓶颈** | 约 5 汉字/秒 | 长文本必须分句下发 |
| **MOVE 距离饱和** | ACK 里的 `mm10` 上限 255 | 超过 25.4 mm 一律显示 `0xFF` |
| **事件是广播的** | A7Z 和蓝牙都能收到 | 不能假设事件独占 |
| **无重传机制** | MCU 不缓存已发的命令 | 丢帧只能靠上位机重发 |

## 14. 附：参考实现

### 14.1 C 版本（推荐，A7Z 侧直接用）

`tools/mcu_link_example.c` —— 可编译运行的完整骨架，只依赖 POSIX。

```bash
gcc -std=c99 -Wall -Wextra -O2 -o mcu_link tools/mcu_link_example.c
./mcu_link /dev/ttyS4 --probe      # PING + 读配置
./mcu_link /dev/ttyS4 --demo       # 前进 2000 步再停
./mcu_link /dev/ttyS4 --monitor    # 只心跳 + 打印事件
```

**它演示了几个容易写错的关键点：**

| 关键点 | 代码位置 |
|---|---|
| CRC 从 SOF 开始算 | `crc16_ccitt_false(out, 6 + len)` |
| 靠 SEQ 配对而不是 OP | `link_ask()` 里比较 `rx_seq` |
| 等应答期间必须继续发心跳 | `link_pump()` |
| 一次 read 可能读到多帧，不能丢 | `pend[]` 缓冲 |
| 退出前先停车 | `main()` 末尾 |

> ★ 其中「一次 read 读到多帧」这一条是实测踩出来的：
> MCU 常常把「ACK + 紧随的事件」一起发出来，
> 如果返回第一帧时把同批的剩余字节丢掉，就会**静默丢事件**。
> 症状是「电机明明走完了，程序还在傻等 MOTION_DONE」。
