# M9 · TTS 语音转发验收说明

> 本文对应项目说明书 §1.1「TTS 帧转发（替代 A7Z 直连 TTS 模块）」。
> **状态：代码完成，未经硬件验收。** 未听到声音之前不要标记为通过。

---

## 1. 为什么 TTS 从 A7Z 挪到 MCU

原方案里 TTS 模块挂在 A7Z 的 UART4 上。后来为了让 A7Z 的 UART4 单独、完整地
服务运动链路（控制帧需要双向、需要低延迟、需要独占），TTS 必须让路。

于是改成：

```text
A7Z ──UART4(115200)──> STM32 ──USART2(9600)──> TW-TTS 模块 ──> 喇叭
        运动 + TTS 文本                     TW-TTS 原始帧
```

A7Z 侧不需要改协议：它已经有验证过的 `tts_text_frame()`，把生成的帧塞进
`OP_TTS` 的负载即可，MCU 原样转发。

**好处**：A7Z 只占用一个串口，TTS 的 9600 慢速通道不会拖累运动链路的实时性。

## 2. 接线

| STM32 | 方向 | TTS 模块 | 说明 |
|---|---|---|---|
| **PA2** | → | **RXD** | USART2_TX |
| **PA3** | ← | TXD | USART2_RX，模块通常不回数据 |
| 5V | — | VCC | 模块含功放，峰值约 200 mA |
| GND | — | GND | **必须共地** |

> ⚠️ **PA3 可以不接。** 只有 PA2 + 5V + GND 三根线就能出声。
> 接上 PA3 的好处是以后能读模块的忙/闲状态。

> ⚠️ **不要用 A7Z 的 3.3V 给模块供电。** 模块带功放，峰值电流会把 A7Z 的
> 3.3V 拉塌，表现为 A7Z 复位或 SD 卡掉盘。

## 3. 固件侧实现要点

### 3.1 绝对不能同步发送

9600 8N1 只有 **960 字节/秒**。一条 60 字的中文句 = 195 字节 = **203 ms**。

如果按"发完再返回"写，主循环会停摆 200 ms：

- 步进 1 ms 节拍断掉 → 电机顿挫甚至失步
- 心跳超时判据被触发 → 安全联锁把动作停掉
- A7Z 的命令帧堆积在环形缓冲里

所以 `Tts_Relay()` **只做一次 memcpy + 下标推进**（几微秒），
真正的移位由 `USART2 TXE` 中断在后台完成。

### 3.2 整帧原子性

环形缓冲放不下时 **整帧拒绝**（返回 `TTS_ERR_BUSY` → NAK `0x02`），
不做"能塞多少塞多少"。

理由：TW-TTS 是流式协议，收到半截帧会**念到一半停住且无法自愈**，
必须复位模块才能恢复。宁可让上位机重发。

### 3.3 两种负载形态

| 负载首字节 | 处理方式 | 用途 |
|---|---|---|
| `0xFD` | 原样转发 | A7Z 正式接入（协议与已验证的 `uart_tts.cxx` 完全一致） |
| 其他 | 当作 UTF-8 正文，MCU 组帧 `FD len 01 04 text` | 台架自测，上位机不用自己算帧头 |

## 4. 帧格式（TW-TTS）

### 文本帧

```text
0xFD | len_hi | len_lo | 0x01 | 0x04(UTF-8) | 正文...
        └────── len = 正文长度 + 2 ──────┘
```

### 参数帧

```text
0xFD | 0x00 | 0x06 | 0x01 | 0x01 | '[' | 'v'/'s'/'t' | '0'..'9' | ']'
```

| 参数 | 含义 | 例 |
|---|---|---|
| `v` | 音量 | `fd 00 06 01 01 5b 76 35 5d` = 音量 5 |
| `s` | 语速 | `fd 00 06 01 01 5b 73 35 5d` = 语速 5 |
| `t` | 语调 | `fd 00 06 01 01 5b 74 35 5d` = 语调 5 |

### 长度上限

| 项 | 上限 | 原因 |
|---|---|---|
| 单帧负载 | 200 字节 | `LINK_MAX_PAYLOAD` |
| 正文 | 190 字节（约 63 个汉字） | 减去 5 字节帧头，再留余量 |

超过一律 NAK `0x01`。A7Z 侧 `SentenceStream` 本来就是按句切的，正常不会超。

## 5. 验收步骤

### 5.1 准备

1. 接线：PA2 → 模块 RXD，5V → VCC，GND 共地
2. 打开 TTS 配置位：`s 0000004e`
3. 重新上电，看开机自检里的这一行：

```text
 tts    : USART2 9600 8N1  PA2(TX)/PA3(RX)  [READY]
```

如果是 `disabled`，说明 `CFG_TTS_EN=0` 或 `TTS_LINK_ENABLE=0`。

### 5.2 一键验收

```cmd
python tools/pc_link_test.py COM3
cmd> ttsdemo
```

`ttsdemo` 会依次做四件事：

| 步骤 | 内容 | 通过标准 |
|---|---|---|
| ① | 三帧参数（音量/语速/语调各 5） | 回 ACK(OK)，模块不报错 |
| ② | 短句「你好，我是桌面陪伴宠物」 | **喇叭出声** |
| ③ | 长句（约 60 字） | 连续念完，不吞字不卡顿 |
| ④ | 200 个「啊」（超长） | **必须被拒 NAK(0x01)** |

### 5.3 单独发一句

```cmd
cmd> tts 测试一下语音
cmd> ttsraw fd000601015b76355d
```

### 5.4 ★ 关键验证：TTS 不能阻塞主循环

这是本阶段最重要的验收项，**比"能不能出声"更重要**。

做法：发一句长句，在它播报的同时立刻发 `st` 和 `p`（PING）。

```cmd
cmd> tts 这是一句很长的测试语句用来验证主循环没有被阻塞住
cmd> st        ← 必须立刻回应 ACK(OK)
cmd> p         ← uptime 必须连续递增，不能跳 200ms
```

**判定：**

| 现象 | 结论 |
|---|---|
| `st` / `p` 秒回 | ✅ 中断发送生效，主循环正常 |
| `st` 要等一两秒才回 | ❌ 说明还在同步发送，回去检查 `Tts_Relay` 是否用了阻塞循环 |
| `p` 的 uptime 跳变 200 ms 以上 | ❌ 同上 |

## 6. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| 完全没声音 | PA2 没接到模块 RXD | 检查接线（TX→RXD 是交叉的） |
| 有电流声/杂音 | 5V 电源纹波大，或与电机共用电源 | 喇叭与电机分开供电，各加 100 µF |
| 念到一半停住 | 曾收到过半截帧 | 断电重启模块；确认固件是"整帧原子入队"版本 |
| NAK(0x06) | 配置字 TTS_EN=0 | `s 0000004e` |
| NAK(0x02) 反复出现 | 上位机发太快，环满 | 每次发完等 1 秒；或降低语速 |
| 首字被吞 | 模块上电初始化慢 | 上电后等 2 秒再发第一条 |
| 乱码/念错 | 正文不是 UTF-8 | 确认上位机用 UTF-8 编码 |

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| **无播放完成回调** | TW-TTS 不回状态。MCU 只知道"字节发完了"，不知道"念完了"。想串行播报只能按字数估算（约 5 字/秒） |
| **单帧 190 字节** | 长文本必须由 A7Z 按句切分，与 `SentenceStream` 的分句粒度一致 |
| **无优先级** | TTS 队列是严格 FIFO。紧急通知无法插队，只能清空整条队列（未实现） |
| **9600 是硬瓶颈** | 约 1 秒只能播 5 个汉字。这不是固件问题，是模块串口上限 |

## 8. 与 A7Z 侧的对接约定

A7Z 把 `uart_tts.cxx` 里 `tts_text_frame()` 生成的字节，原样放进
`OP_TTS` 的负载即可，**不需要任何转换**。

对接时唯一要改的：把原来 `write(fd, frame)` 换成往 UART4 的二进制链路里发包。

```text
原来：  tts_text_frame() -> write(/dev/ttyS4, frame)
现在：  tts_text_frame() -> OP_TTS 负载 -> UART4 -> MCU -> USART2 -> 模块
```

参数帧（音量/语速/语调）同样处理，走 `OP_TTS` 原样转发。
初始化时机由 A7Z 控制：连上链路后先发三帧参数，再发正文。
