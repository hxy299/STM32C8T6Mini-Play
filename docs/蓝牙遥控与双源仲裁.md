# 蓝牙遥控与双命令源仲裁

> 目标：**A7Z 不在场时，STM32 仍能被蓝牙遥控独立操作**，
> 同时保证两个命令源不打架、任何情况下都不会把主循环卡死。

---

## 1. 硬件接线

| 信号 | STM32 | 模块（HC-05 / HC-06 / JDY-31） |
|---|---|---|
| TX | **PB10**（USART3_TX） | 模块 **RXD** |
| RX | **PB11**（USART3_RX） | 模块 **TXD** |
| 电源 | 3.3 V 或 5 V（按模块铭牌） | VCC |
| 地 | GND | GND |

> **PB10 / PB11 是 USART3 的默认引脚**，无需重映射。
> RX 内部已开上拉 —— 模块没插时不会因为悬空噪声不断触发解析。

---

## 2. ⚠️ 波特率必须先改（最容易踩的坑）

**HC-05 / HC-06 出厂默认 9600**，而固件里 `BT_UART_BAUDRATE = 115200`。

### 为什么要改

| 波特率 | 一个 20 字节应答帧的发送时间 |
|---|---|
| 9600 | **20.8 ms** |
| 115200 | **1.7 ms** |

9600 下每一帧都要阻塞主循环 20 ms，A7Z 链路和步进任务全被拖慢 ——
这正是"程序卡死"最直接的来源。

### 怎么改（HC-05）

模块**断电状态下按住 KEY/EN 键上电**进入 AT 模式，波特率 38400：

```
AT                 -> OK
AT+UART=115200,0,0 -> OK
AT+RESET           -> OK
```

改完断电重启，之后就是 115200 了。

> **改不了怎么办**：把 `BT_UART_BAUDRATE` 改成 `9600u` 重新编译。
> 此时务必保持 `BT_VERBOSE_EVENTS = 0`（默认就是 0），
> 否则高频遥测会把发送端堵死。

---

## 3. 启用蓝牙

配置字里 `CFG_BT_EN` 是 **bit2 = 0x04**。

```
默认值（两颗 TOF）：0x4E = TTS + BT + TOF0 + TOF3
```

**已经烧过固件的板子**配置存在 Flash 里，改 `CFG_DEFAULT` 宏不会生效，需要手动发一次：

```cmd
cmd> s 0000004E
```

上电横幅确认：

```
 bt     : USART3 115200 8N1  PB10(TX)/PB11(RX)  [READY]
```

如果是：

```
 bt     : disabled (CFG_BT_EN=0, BT_LINK_ENABLE=1)
```

说明配置位没打开 → 发 `s 0000004E`。

## 4. 双命令源仲裁规则

### 控制权归属

| A7Z | 蓝牙 | 控制权 | 说明 |
|:--:|:--:|---|---|
| 在线 | 在线 | **A7Z** | A7Z 是"大脑"，优先 |
| 在线 | 离线 | A7Z | 正常模式 |
| 离线 | 在线 | **蓝牙** | **这就是"单独用蓝牙遥控"** |
| 离线 | 离线 | 无 | 置 `HEARTBEAT_LOST` 并停车 |

### 命令优先级（数值越小越优先）

| 等级 | 命令 | 是否受控制权限制 |
|---|---|---|
| **SAFETY** | `MOTOR_STOP`、`CLEAR_FAULT`、**`MOVE dir=STOP`** | ❌ **任何来源、任何时候都执行** |
| **QUERY** | `PING`、`GET_CONFIG`、`STEPPER_STAT`、`LINK_STAT` | ❌ 总是执行 |
| **CONTROL** | `MOVE`（非 STOP）、`SERVO`、`TTS`、`TOF_CFG`、`SET_CONFIG`、`STEPPER_TEST` | ✅ **只有拥有者能执行** |

**为什么 SAFETY 不受限制：**
遥控器上的"停"必须永远有效。如果连停止都要仲裁，
A7Z 占着控制权时蓝牙就停不了车 —— 紧急情况下这是致命的。

**非拥有者发 CONTROL 会收到：**

```
NAK(0x09 ARBITRATION, op)
```

### 控制权切换时强制停车

```
A7Z 正在让它前进 → A7Z 掉线 → 蓝牙接管
                                  ↓
                          立刻 Stepper_StopAll()
```

不这么做，机器人会"接着 A7Z 那条命令继续跑"，
在没有桌沿保护的情况下非常危险。反向切换（蓝牙 → A7Z）同样停车。

## 5. 防卡死的 8 项措施

这是本功能的核心。逐条对应一个真实的卡死路径：

| # | 措施 | 防的是什么 |
|:--:|---|---|
| 1 | **每端口独立解析器实例** | 两路共用一个状态机会互相吞字节，**接了蓝牙以后 A7Z 也失灵** |
| 2 | **每端口每轮最多处理 32 字节**（`LINK_PORT_BYTE_BUDGET`） | 一路被噪声刷屏会把主循环占死，另一路和步进任务被饿死 |
| 3 | **每端口独立的 100 ms 帧间超时** | 假 SOF 带大 LEN 的半帧会把后续真帧吞掉 |
| 4 | **环形缓冲溢出只计数不阻塞** | 中断里绝不等待，满了就丢新字节 |
| 5 | **蓝牙波特率强制 115200** | 9600 下一帧阻塞 20 ms |
| 6 | **蓝牙不给高频遥测**（`BT_VERBOSE_EVENTS=0`） | TOF_DATA 每 200 ms 一条，低波特率下会积累成阻塞 |
| 7 | **统一控制权，切换即停车** | 两个源同时驱动电机，脉冲互相覆盖、位置计数全乱 |
| 8 | **蓝牙独立失联超时**（2000 ms） | 蓝牙断开后仍以为能控制 |

**全程没有任何"等待对端"的循环。** 唯一的阻塞点是 UART 发送（有界）。

## 6. 协议：完全复用现有的二进制帧

**没有引入第二套协议。** 蓝牙走的是同一个 `A5 | TYPE | SEQ | OP | LEN | PAYLOAD | CRC16` 帧格式。

好处：

- **PC 测试工具可以直接用**：电脑配对 HC-05 后会多出一个虚拟 COM 口，
  直接 `python tools/pc_link_test.py COM8` 就能全功能遥控
- CRC、ACK/NAK、所有操作码、所有诊断命令全部复用
- 不需要另写一套手机 App 协议

### 应答往哪发

- **ACK / NAK / PONG** → 发回**发起请求的那条链路**
- **事件**（FAULT / MOTION_DONE / EDGE / OBSTACLE）→ 广播给所有在线链路
- **TOF_DATA** → 默认只发 A7Z（高频，蓝牙不需要）

### LINK_STAT 扩展

payload 从 26 字节扩到 **32 字节**（向后兼容，旧工具只读前 26 字节）：

| 偏移 | 内容 |
|---|---|
| `[0..25]` | **发起查询那条链路**的统计（A7Z 问就是 A7Z，蓝牙问就是蓝牙） |
| `[26]` | 当前控制权：`0`=A7Z，`1`=蓝牙，`0xFF`=无人 |
| `[27]` | A7Z 在线 |
| `[28]` | 蓝牙在线 |
| `[29]` | 蓝牙是否已初始化 |

`lstat` 命令会显示：

```
  ---- 双链路 ----
  控制权        : A7Z
  A7Z  在线     : YES
  蓝牙 在线     : no
  蓝牙 已初始化 : YES
```

## 7. 验收步骤

### 7.1 单独用蓝牙控制（核心场景）

**前提：拔掉 A7Z 的串口线**（模拟 A7Z 不在场）。

```cmd
# 电脑蓝牙配对 HC-05，记下虚拟 COM 口（例如 COM8）
python tools/pc_link_test.py COM8
```

| 步骤 | 预期 |
|---|---|
| `v` | 返回 `/PONG`，`impl` 正常 |
| `lstat` | 控制权 = **蓝牙**，A7Z 在线 = no，蓝牙在线 = YES |
| `fwd 500` | **ACK(OK)，电机真的动** |
| `st` | 立即停 |

**这一步能通过，就说明"单独蓝牙遥控"成立。**

### 7.2 蓝牙 + A7Z 同时在线

两路都接上：

| 从哪发 | 命令 | 预期 |
|---|---|---|
| A7Z | `fwd 500` | ACK，动 |
| **蓝牙** | `fwd 500` | **NAK(0x09 ARBITRATION)** ← 控制权在 A7Z |
| **蓝牙** | `st` | **ACK，真的停** ← SAFETY 不受限 |
| 蓝牙 | `p` | PONG ← QUERY 不受限 |

### 7.3 控制权切换

| 步骤 | 预期 |
|---|---|
| A7Z 发 `fwd 2000`（正在跑） | 电机前进 |
| **拔掉 A7Z 的串口线** | 电机**立刻停**（控制权切换） |
| 蓝牙发 `bck 500` | ACK，电机后退 ← 蓝牙接管成功 |

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 横幅显示 `bt: disabled` | `CFG_BT_EN=0` | 发 `s 0000004E` |
| 能连上但收不到应答 | **波特率不匹配**（模块还是 9600） | 用 AT 命令改到 115200，或把 `BT_UART_BAUDRATE` 改 9600 |
| 收到乱码帧 / 坏帧数猛涨 | 同上，或线序接错（TX/RX 没交叉） | 交换 PB10/PB11 的接线 |
| `lstat` 里蓝牙在线一直是 no | 帧到了但 CRC 错 | 看 `lstat` 的「好帧/坏帧」比值 |
| 蓝牙发 MOVE 返回 `NAK 0x09` | **这是正常的** —— A7Z 在线，控制权不在蓝牙 | 拔掉 A7Z 或先发 `st` |
| A7Z 侧突然失灵 | 解析器被共享（本设计已避免） | 确认烧的是本版固件 |
| 整机卡顿 | 蓝牙在刷屏且配额失效 | 确认 `LINK_PORT_BYTE_BUDGET` 生效 |

## 10. 已知限制

| 限制 | 说明 |
|---|---|
| 蓝牙无认证 | HC-05 配对后任何数据都接受；不做法应用层加密 |
| 只有一条 BT 链路 | 一次只能配对一个设备（HC-05 本身如此） |
| 蓝牙不参与故障仲裁 | 蓝牙在线不能覆盖桌沿/过热故障，安全故障仍需 `CLEAR_FAULT` |
| 复位后需重新配对 | HC-05 配对信息保存在模块里，不受 MCU 复位影响 |
| 9600 也可用但慢 | 改不了波特率时可用，代价是主循环被拖慢 |
